# Blog content brief — for the daily automated post routine

This file is read by an automated agent that has zero prior context about this project. Follow it exactly. Do not skip steps or improvise structure — only the prose content is yours to write.

## Who this is for

Kavin Arulraj, a freelance graphic designer / web designer / video editor in Chennai. The site (`kavinarulraj.com`) is 100% hand-authored static HTML — no CMS, no build step, no framework. Voice: practical, direct, written for small-business owners (not designers). No jargon, no "top 10 fonts" listicles, no generic AI-blog padding. Short concrete examples, real ₹ figures where relevant, Chennai/Tamil Nadu context. Match the tone of the 8 existing posts in `blog/`.

## Hard rules — do not violate

1. **Never invent a new named client, project, testimonial, or result.** The only real portfolio work that exists is:
   - `portfolio/case-study-madras-filter-coffee.html` — packaging redesign for a small-batch filter coffee roaster (4-SKU pouch line, bilingual Tamil/English labels, FSSAI-compliant back panel, picked up by 3 retail stores).
   - `portfolio/case-study-omr-clinic.html` — booking-flow redesign for a multi-speciality clinic on OMR (cut a 7-screen flow to one decision by removing fields, more bookings on the same traffic, 2-week timeline).
   - `portfolio/case-study-wedding-film.html` — wedding video edit (14 hrs of 3-camera footage cut to a 4:10 film, 3-week turnaround).
   A "case-study angle" post must only reference one of these three, from a different angle each time (see `.blog-rotation.json`), and must not state any fact not already present in that case study's page. When in doubt, write generically ("in booking-flow projects like this one...") rather than inventing a specific new number or quote.
2. **General tips posts stay generic.** No fabricated statistics, no invented client quotes, no "a client of mine once...". Write from general professional knowledge the way the existing 8 posts do.
3. Never touch `main` directly, never merge your own PR. Open a **draft PR** and stop.
4. Never modify any file other than the ones listed in "What to update" below, plus `.blog-rotation.json`.

## What to update, every run (all 4 required)

1. **New file** `blog/<slug>.html` — the post itself.
2. **`blog.html`** — insert one new entry at the *top* of the `#flt-1` grid (most recent first), and update the `<p>N posts</p>` counter just below the grid.
3. **`sitemap.xml`** — append one new `<url>` line in the `/blog/` section (after the existing blog URLs, before the closing of that group), with `changefreq=yearly`, `priority=0.5`, `lastmod` = today's date (YYYY-MM-DD).
4. **`.blog-rotation.json`** — mark the topic you used as consumed (see that file's own structure/comments).

## Slug and URL convention

Lowercase, hyphenated, no dates in the slug (matches all 8 existing posts, e.g. `how-many-logo-concepts`, `logo-signboard-problems`). The live URL is `/blog/<slug>/` (trailing slash, clean URL per `vercel.json`) but the file on disk is `blog/<slug>.html`.

Do not add an `<img>` for a cover image — no existing blog post uses one (confirmed: none of the 8 posts or the list entries in `blog.html` render an image). Stay consistent with that; an all-text post is the established pattern.

## PR

Branch name: `blog/<slug>`. Commit message: short, describing the post. Open a **draft PR** titled with the post's headline, body summarizing what was added (post + blog.html entry + sitemap entry + rotation state) and which topic/angle was used from `.blog-rotation.json`. Do not merge it.
