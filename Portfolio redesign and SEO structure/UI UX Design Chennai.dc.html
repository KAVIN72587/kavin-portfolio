The states most designs skip

A screen has one happy path and about five other conditions. Leave those out and your developer invents them, which is how a polished mockup ships as an inconsistent product.

  • Empty

    The first screen every new user sees. Designing it with three rows of dummy data hides the problem entirely.

  • Loading

    On Indian mobile data this state is visible often. Skeletons, not a centred spinner on white.

  • Error

    What actually went wrong and what to do next — not "Something went wrong."

  • Too much content

    The user with a 40-character name and 200 items. Layouts break here, not at the average.

  • Disabled & in-progress

    Buttons mid-submit, forms partially valid. Specified so nobody double-taps and pays twice.

  • Offline

    Connectivity drops mid-task constantly here. The app should say so rather than freeze.

How a project runs

  1. STEP 01

    Flows before screens

    What the user is trying to finish, and the shortest route there. Boxes and arrows, no styling.

  2. STEP 02

    Wireframes

    Grey boxes with real copy. Cheapest possible stage to discover the flow is wrong.

  3. STEP 03

    Hi-fi & prototype

    Full visual design, clickable, on a real phone. You test it before anyone writes code.

  4. STEP 04

    Developer handover

    Component library, spacing scale, all states, and a call with your engineer to walk it through.
