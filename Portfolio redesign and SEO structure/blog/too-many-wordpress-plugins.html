Your WordPress plugin list needs a clear-out

Open the plugins page on many small business WordPress sites and you find thirty, forty, sometimes sixty plugins. Some do the same job twice. Some were installed to test something years ago. Some have not been updated by their developers in years. Each one is code running on your site.

Here is why the quality of plugins matters more than the number, how plugins cause slowness, conflicts and security problems, and a simple way to audit your list and keep it lean.

01

It is not really about the number

There is no magic limit. A site with twenty well-made, actively maintained plugins can be fast and secure. A site with eight poorly made or abandoned ones can be slow and vulnerable. What matters is what each plugin does, how well it is built, whether it is maintained and whether you actually need it.

That said, every plugin is one more thing to update, one more possible conflict and one more potential security hole. Fewer is easier to look after.

02

How plugins slow sites down

Some plugins add code and styles to every page, even pages where they are not used. Sliders, page builders, social feeds, chat widgets and some form plugins are common culprits. Others run heavy database queries or call external services. Individually the cost may be small; together, they add up to a slow site, especially on mobile.

03

Conflicts and broken updates

Plugins are written by different developers. When WordPress or one plugin updates, another may break, causing a white screen, a broken layout or a form that stops sending. The more plugins you have, the more combinations can conflict. This is why updates should be done after a backup, ideally tested on a staging copy first.

04

Abandoned plugins are a security risk

Plugins that have not been updated in a long time may contain known vulnerabilities that will never be fixed. Automated attacks look specifically for these. The WordPress plugin directory shows when each plugin was last updated and whether it has been tested with recent WordPress versions. A plugin untouched for years is a candidate for replacement.

Never use pirated (nulled) premium plugins. They are a common way malware gets into sites.

05

Audit your list

Go through every plugin and ask: what does it do, is it used, is there another plugin doing the same job, when was it last updated, and is it from a reputable developer? Deactivate anything unused, then delete it; deactivated plugins can still be a risk if left installed. Replace overlapping plugins with one good one.

06

What a small business site typically needs

Most small business WordPress sites need only a handful of plugin types: a contact form, an SEO plugin, a backup plugin, a security or login protection plugin, a caching or performance plugin (often provided by the host), and possibly an image optimisation plugin. Ecommerce adds WooCommerce and its payment and shipping extensions. Beyond that, each addition should earn its place.

07

Prefer theme and core features

Many things people install plugins for can be done with WordPress itself or a good theme: simple galleries, buttons, columns, embedded maps and videos. A few lines of code added by a developer can replace a whole plugin for a small task, such as adding an analytics tag. Less third-party code means fewer things to break.

Page builders deserve a special mention: they are convenient but heavy, and switching away from one later is a big job.

Every plugin is a commitment

Installing a plugin takes seconds. Keeping it updated, compatible and secure is a long-term job. Before adding one, ask whether the feature is worth that ongoing commitment, or whether there is a simpler way.

Install deliberately, update regularly, delete what you do not use.

Review the plugin list every few months as part of routine maintenance. It is one of the cheapest ways to keep a WordPress site fast and safe.

Plugin audit questions

  1. Is it used? If not, deactivate and delete.
  2. Is it duplicated? Keep one plugin per job.
  3. Is it maintained? Recent updates and tested with current WordPress.
  4. Is it heavy? Does it load on pages where it is not needed?
  5. Is it legitimate? From the official directory or a reputable developer, never nulled.

Take a full backup before removing plugins, and check the site's pages and forms after each removal. Some plugins leave settings or shortcodes behind that need tidying up.

Quick answers

How many plugins should a WordPress site have?

There is no fixed limit. Quality, maintenance and need matter more than the number. Most small business sites work well with a handful of well-maintained plugins.

Do plugins slow down WordPress?

Some do, especially those that load code on every page or run heavy queries, such as sliders, page builders and social feeds. Removing unnecessary ones often improves speed.

Should I delete deactivated plugins?

Yes. Deactivated plugins can still pose a security risk if left installed. Delete plugins you no longer use, after a backup.
